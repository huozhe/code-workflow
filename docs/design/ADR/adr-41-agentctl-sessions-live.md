# ADR-41: `agentctl sessions --live` — the Set From `list_nonterminal_sessions`, the Fields From the Row It Does Not Carry

*A decision of record for `agentd`. Index and context: [unified design spec §16](../unified_design_spec.md#16-architecture-decision-records).*


*Resolves #248.* `agentctl sessions` prints every session as full JSON, `CLOSED` ones included. The question actually asked of it — *is anything live right now* — is answered today by a three-line Python snippet copy-pasted into `docs/ops/live-sign-offs.md` step 1 and into per-checkout notes. `agentctl sessions --live` prints one line per non-terminal session and nothing else. It is chosen the way ADR-13 (`agentctl version`) and ADR-14 (`agentctl review-stats`) were: the value is that the loop runs end to end, with the extra property that it retires a snippet from the runbook this session is executing.

**Membership is `Store.list_nonterminal_sessions()` called for the set — no predicate is written beside it.** The issue is right that a second definition of "live" is how two components come to disagree about the same word, and the sweep's definition (`db.py:581`, whose clause is `state NOT IN ('CLOSED', 'TEARDOWN')` at `:591`) is the one that already exists. `--live` calls that method and renders what comes back. Measured against a five-row fixture holding `INTAKE`, `IMPLEMENTING`, `PAUSED_HUMAN`, `TEARDOWN` and `CLOSED`, it returns the first three.

**The fields come from `Store.get_session()`, the enrichment step bare `sessions` already runs — because `list_nonterminal_sessions` does not carry three of the six the line needs.** Its `SELECT` names fifteen columns and `turn_count`, `silent_turns` and `updated_at` are not among them; this was measured, not read. So membership and presentation are answered by two different calls, which is exactly the shape `agentctl sessions` has today (`list_sessions()` for the set, `get_session()` per row for the fields). The alternative — widening the sweep's `SELECT` by three columns — is one query instead of N+1 and closes a nanosecond-wide race where a session is deleted between the two calls, but it edits the query `reconciler._sweep_github` depends on in order to add a read-only CLI flag. The N+1 runs over a bounded set on an on-demand command; the race resolves by falling back to the membership row. Neither cost is worth reshaping the sweep, and a reviewer should not have to reason about whether an added column can reach `_apply_snapshot`.

**Ordering is `updated_at DESC, session_key ASC`, applied in the CLI.** `list_nonterminal_sessions` has no `ORDER BY` — it returned insertion order in the fixture — so a human-facing list has to impose one, and the CLI is where presentation belongs. `updated_at DESC` is chosen because it is what bare `sessions` already orders by, so a reader moving between the two commands sees the same order. `session_key ASC` is not decoration: `updated_at` is written as `int(time.time())`, whole seconds, and in the fixture every row tied. Without the second key the acceptance test asserts against an order SQLite is free to change.

**Output is ASCII. The absent-PR placeholder is `-`, not `—`.** The issue's suggested line uses an em dash, and it was tried before being rejected: under `PYTHONIOENCODING=ascii`, `print('—')` raises `UnicodeEncodeError` and exits **1**, which would break this command's own acceptance that its exit status is always 0. A `LANG=C` locale is *not* the hazard — PEP 540 gives that a UTF-8 stdout — the explicit encoding override is. The whole reason this command exists is to be pasted into runbooks, sign-off records and issue bodies, and one lossy hop is enough. Every other field is ASCII by construction: `session_key` is `repo#issue`, `state` is a closed vocabulary (`fsm.SESSION_STATES`), the rest are integers.

**No header row, in either the populated or the empty case.** The acceptance is that a DB with no live sessions prints *nothing* to stdout. A header would either be printed above zero rows — which is the "None" the issue rules out, spelled differently — or the command would have two output shapes depending on row count. One shape, no header.

**`paused_reason` is not on the line.** A `PAUSED_HUMAN` session's reason is the actionable part, and it is still the wrong thing to put here: it is free text truncated at 500 characters (`session_loop.py:2180`), it is written from agent- and owner-authored text (`:2997`), and the escalation text this project actually generates contains an em dash (`loop_safety.py:129`) — the hazard the placeholder decision above just removed. One line per session is the contract that makes the output greppable; bare `agentctl sessions` still prints `paused_reason` in full.

**`turns=` is `sessions.turn_count`, not `Store.count_turns()`.** `turn_count` is §9.2's budgeted counter, already on the row `get_session` returned. `count_turns()` is a second query per session and counts teardown turns as well — a distinction `--live` can never show, since it does not list `TEARDOWN`.

**Bare `agentctl sessions` is unchanged, and gains the characterization test that claim currently lacks.** `--live` is `action="store_true"`, default `False`; the existing branch is untouched. But there is no test for `agentctl sessions` at all today, so "byte-identical to today's output" is presently unguarded — the implementation PR adds a test that pins the bare JSON and is shown to fail when the bare path is perturbed.

**Named residual: there are already two definitions of terminal, and this ADR does not merge them.** `fsm.TERMINAL_STATES` is `frozenset({"TEARDOWN", "CLOSED"})`; `db.py:591` repeats the same two states as a SQL literal. Unifying them means parameterising the sweep's `IN` clause from an import, and `fsm` is a leaf module so no cycle forbids it — but that is a change to the sweep's query, made for tidiness, in a PR whose subject is a read-only flag. Instead the implementation PR adds a test asserting the two sets agree, which catches divergence at zero behavioural risk. Merging them is left to whoever next has reason to touch that query.

**`--live` is not a drop-in for the runbook's step 1, and the runbook must say so.** Step 1 of *Running the exercise* asks "confirm nothing is live — a session in flight makes every observation ambiguous", and its snippet filters on `state != 'CLOSED'` only, so it shows a `TEARDOWN` session. `--live` will not. That is not a defect in the definition: a `TEARDOWN` session is one the owner has closed, and excluding it from "sessions in the loop" is correct. It *is* a narrowing of the check, because `_run_teardown_turns` dispatches two full agent turns for both roles while the session is in `TEARDOWN` (`session_loop.py:3255`, inside `_run_teardown_turns` at `:3167`), and that state can stick across drains (`_TEARDOWN_DEFER`). Swapping the snippet for `--live` and saying nothing else would replace a check that catches a running teardown with one that does not. The runbook therefore keeps one command for the loop question and names the other instrument for the turn question: `agentctl reconcile --dry-run` reports `open_turns` (`reconciler.py:463`) for every session regardless of state.

*Rejected: `agentctl sessions --json` / a `--format` matrix.* The bare command is already the JSON one and the issue notes something may parse it. Two commands, two audiences, no format flag.

*Out of scope, by the issue:* no change to `list_nonterminal_sessions` or to the sweep; no change to bare `sessions` output; no filtering by state, repo or role; no `agentd` (gateway-process) equivalent. `.claude/STATE.md` also carries the snippet and is gitignored (`.gitignore:6`), so no PR can update it — `docs/ops/live-sign-offs.md` is the only in-repo copy.
